# 执行协议（施工图纸）模板

> 用法：复制到项目根目录，开工第一天和 AI 一起把项目拆成 Step 填进总表。
> 它是给 AI 看的施工图纸：人定义"做什么、验收什么"，AI 负责"怎么做"。

---

## 总则

1. 项目按 Step 0 ~ N 顺序推进，每一步是**可独立验收的增量**
2. **严禁跳步**：进入 Step N+1 前，必须有 Step N 的快照或当日 changelog 佐证
3. 每步完工标准：测试脚本断言全部通过 + 快照已写入 + changelog 已记录
4. "AI 说做完了"不算完工，检查通过才算完工

## Step 总表（按项目填充）

| Step | 名称 | 交付物 | 验收标准 | 状态 |
|------|------|--------|----------|------|
| 0 | 脚手架初始化 | 目录结构 + 验证脚本 | 验证脚本断言全过 | ☐ |
| 1 | （示例）数据库模型 | 建表脚本 + 幂等校验 | 断言全过 | ☐ |
| 2 | （示例）配置管理 | 配置加载 + 异常拦截 | 断言全过 | ☐ |
| 3 | | | | ☐ |
| 4 | | | | ☐ |
| 5 | | | | ☐ |

> 拆步原则：每步只做一个层面的事（建表 / 校验配置 / 解析 / 存库分开），出了问题能快速定位。

## 快照规则

- 路径：`snapshots/step<N>_snapshot.json`
- 格式：见 `snapshot_template.json`
- 快照必须包含 `human_readable_summary`（人话总结）——新会话靠它恢复上下文

## 快照恢复协议（快照丢失时）

1. 优先读 changelog 重建简版快照
2. changelog 不足以重建，则从 Step 0 重新执行
3. **严禁凭记忆跳步**

## 变更管理

- 任何代码修改前，AI 先报方案（改哪些文件、怎么改、为什么），人确认后执行
- 每步范围变更（加需求/改验收）须更新本表并记入当日 changelog
